# 网站安全加固部署记录

> 部署时间：2026-07-15 22:53 ～ 22:58（Asia/Shanghai）
> 生产地址：<https://jbksy.cn>
> 发布提交：`596c239 新增网站安全防护`

## 1. 本次目标

为 Nuxt 网站补齐第一批公网安全防护，并将经过验证的改动部署到生产：

- 杜绝生产环境使用默认或弱管理员启动凭据。
- 降低登录暴力破解、API 滥用和内存耗尽风险。
- 限制跨站写请求与异常大的请求体。
- 增加浏览器安全响应头，隐藏应用与 Nginx 的具体版本。
- 在不影响正常后台登录的前提下完成生产密码轮换。

## 2. 代码变更

### 2.1 管理员启动防护

- `server/plugins/00.init-admin.ts`：生产环境要求 `ADMIN_USERNAME` 已配置，且 `ADMIN_PASSWORD` 至少 16 位、不能为默认值；不满足时以退出码 `1` 停止进程。
- `.env.example`：移除默认密码示例，改为随机强密码占位值。

### 2.2 登录与 API 限流

- 登录失败记录由“仅用户名”改为“来源 IP + 用户名”。
- 登录失败记录与 API 访问记录均设置最大容量，避免攻击者用随机键无限占用 Node 进程内存。
- 全部 `/api/` 请求增加应用层频率限制；Nginx 再增加一层 IP 限流。
- 登录用户名最大 128 字符、密码最大 1024 字符。

### 2.3 写请求约束

- 所有 API 写请求校验 `Origin` 必须与 `NUXT_PUBLIC_SITE_URL` 一致。
- 带正文的写请求要求 `application/json`。
- 应用层限制写请求最大 256 KB；Nginx 同步限制 `client_max_body_size 256k`。
- 登出请求改为发送空 JSON 对象，以满足统一的写请求校验。

### 2.4 响应头与生产配置

- 新增 Content-Security-Policy、HSTS、X-Content-Type-Options、X-Frame-Options、Referrer-Policy、Permissions-Policy、COOP 和 CORP。
- 生产构建关闭 Nuxt DevTools。
- Nginx 对上游隐藏 `X-Powered-By`，并开启 `server_tokens off`，不再泄露 Nginx 具体版本。

## 3. 生产服务器变更

### 3.1 变更前备份

在任何写入操作前完成了 SQLite 一致性备份和 Nginx 配置备份：

- 数据库备份：`/var/lib/jbksy/backups/db-before-security-20260715225326.sqlite`
- Nginx 站点配置：`/etc/nginx/conf.d/jbksy.conf.bak-<timestamp>`
- Nginx 主配置：`/etc/nginx/nginx.conf.bak-<timestamp>`

服务器未安装 `sqlite3` CLI，因此数据库备份改由项目已安装的 `better-sqlite3` 的 backup API 执行，避免直接复制 WAL 数据库文件造成不一致。

### 3.2 Nginx 加固

生产 Nginx 配置完成以下调整，并已通过 `nginx -t` 后热加载：

```nginx
limit_req_zone $binary_remote_addr zone=jbksy_api:10m rate=30r/m;

location ^~ /api/ {
    limit_req zone=jbksy_api burst=20 nodelay;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_hide_header X-Powered-By;
}

client_max_body_size 256k;
server_tokens off;
```

`X-Forwarded-For` 现在由 Nginx 使用 `$remote_addr` 覆盖写入，避免客户端自行伪造来源 IP 绕过应用限流。

### 3.3 管理员密码轮换

- 发现原生产管理员密码长度为 8，不符合新版本的启动要求。
- 已在服务器生成新的 16 位随机密码，写入 `/etc/jbksy.env`，并使用 bcrypt 成本参数 12 更新 SQLite 中对应管理员的密码哈希。
- 明文密码不写入仓库、部署文档或日志；仅在本次受控交付中单独提供给管理员。

## 6. 回滚与后续运维

如本次 Nginx 调整需要回退，先恢复对应的时间戳备份文件，执行 `sudo nginx -t` 后再 `sudo systemctl reload nginx`。

如应用版本需要回退，使用既有部署脚本：

```bash
ssh aliyun-jbk "/opt/jbksy/deploy.sh --ref <历史提交>"
```

注意：应用代码回退不会自动恢复管理员密码或数据库内容。若必须回退数据库，使用本次创建的 SQLite 备份，并在维护窗口内执行恢复与服务重启。

- 定期运行依赖漏洞审计，并验证数据库备份的实际恢复流程。
