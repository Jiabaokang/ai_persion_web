# 智识花园暖纸风整站重设计规格

## 1. 设计结论

本次整站重设计以 Product Design 第二版“编辑手记”为唯一主视觉目标：

- 主结构采用左侧固定导航、中部内容主栏、右侧阅读索引或辅助信息栏。
- 视觉基调采用现代暖纸编辑部，而不是复古仿古网站。
- 融合第一版的克制水墨植物细节，以及第三版的档案分隔线和印刷网格秩序。
- 移除现有深色极光、玻璃拟态、彩色渐变和大面积发光阴影。
- 所有公开页面、登录页和管理后台使用统一设计令牌、排版比例和交互反馈。

## 2. 目标与成功标准

### 2.1 目标

1. 建立覆盖整站的“暖纸数字花园”视觉语言。
2. 让博客、笔记、灵感、公众号和 AI 导航在统一框架中各有清晰层级。
3. 提升长文 Markdown 的阅读质量和内容元素完整度。
4. 将后台编辑器切换为真正以 Markdown 源文本为核心的编辑体验。
5. 支持从本地导入 `.md` 和 `.markdown` 文件后继续编辑、预览和保存。
6. 保持现有 Nuxt、Nitro、Drizzle、SQLite API 与数据模型边界。

### 2.2 成功标准

- 桌面端所有主要路由共享一致的纸张背景、字体、颜色、间距和分隔线。
- 移动端宽度 390px 时无横向滚动、文字截断或屏幕外主要操作。
- 长文正文行宽控制在约 60–65 个中文字符以内。
- Markdown 标题、段落、列表、引用、链接、表格、图片、行内代码和代码块均有明确样式。
- 编辑器支持“编辑 / 分屏 / 预览”模式，且保存内容仍写入现有 `contentMd` 字段。
- 本地 Markdown 文件导入不会自动上传文件，只在浏览器本地读取文本并写入编辑器。
- 导入、预览、保存和快捷键操作均有可感知反馈。
- 现有公开/私密、草稿/发布、内容类型和标签逻辑保持不变。

## 3. 视觉系统

### 3.1 色彩

使用以下语义化设计令牌替换极光体系：

- 页面底色：暖象牙纸 `#F3EBDD`。
- 主内容纸面：浅奶油 `#F8F2E7`。
- 次级纸面：燕麦色 `#E9DECC`。
- 主文字：墨褐 `#2A241D`。
- 次级文字：灰褐 `#6F6558`。
- 弱化文字：浅灰褐 `#968B7C`。
- 主要强调：陶土红 `#B85C38`。
- 次级强调：苔藓绿 `#667653`。
- 分隔线：纸墨线 `rgba(71, 59, 43, 0.18)`。
- 聚焦轮廓：陶土红半透明外圈。

不使用彩色渐变。阴影仅用于浮层、抽屉和需要表达层级的菜单，正文布局以留白和细分隔线区分。

### 3.2 纸张质感

- 背景使用一张轻量、可平铺的真实纸张纹理资源。
- 纹理对比度必须低，不影响正文可读性。
- 正文纸面可叠加极轻微噪点，但不模拟折痕、污渍或破损。
- 不使用 CSS 绘制植物或装饰图；水墨植物作为独立图片资源使用。

### 3.3 字体与排版

- 展示与长文标题：中文宋体/明体风格字体。
- UI、按钮、表单和辅助信息：清晰的中文无衬线字体。
- 代码：等宽字体。
- 全站最多使用两套正文家族，代码字体不计入。
- 文章正文使用更大的行高和克制段间距，优先保证长时间阅读舒适度。

### 3.4 形状与图标

- 圆角收紧为 4–10px，避免全站胶囊化。
- 普通内容列表不做卡片堆叠，使用行、组和分隔线表达关系。
- 图标使用项目现有 Iconify/Carbon 能力中最贴近编辑部风格的一套线性图标。
- 品牌“智”字方章保留，但改为单色陶土红印章。

## 4. 全局布局

### 4.1 桌面端

公开页面使用三栏框架：

1. 左栏：品牌、主导航、主题/设置入口；宽度稳定，滚动时保持可见。
2. 中栏：页面主要内容，拥有最强视觉权重。
3. 右栏：阅读索引、近期内容、标签或当前页面目录；仅展示与当前任务有关的信息。

文章详情页可以收窄主栏，并将右栏切换为文章目录和元数据。AI 导航页允许中栏增宽，以容纳搜索和分类结果。

### 4.2 移动端

- 折叠左侧导航为顶部品牌栏和抽屉。
- 右侧辅助栏移入正文之后，或变为可展开目录。
- 主要内容保持单栏。
- 编辑器工具栏允许横向滚动，但保存、预览和导入不得被隐藏。
- 触控目标最小 44px。

## 5. 页面映射

### 5.1 首页 `/`

- 中栏顶部呈现站点宣言和最新文章。
- 内容列表以编辑部文章流呈现，减少独立卡片。
- 明确提供“写文章”和“导入 .md”入口；未登录时跳转登录页。
- 右栏展示近期笔记、灵感和一句知识摘录。

### 5.2 博客 `/blog` 与 `/blog/:slug`

- 列表按编辑部文章流展示标题、摘要、标签、时间和阅读时长。
- 详情页采用书页式窄正文。
- 右栏展示目录、发布日期、阅读时长和相关内容。
- 代码块、引用、表格、图片和链接必须具备独立视觉层级。

### 5.3 笔记 `/notes` 与 `/notes/:slug`

- 列表密度高于博客，强调时间和标签。
- 详情页继续使用统一 Markdown 排版，但标题尺度低于博客。

### 5.4 灵感 `/inspiration` 及新建/编辑页

- 使用轻量时间线或卡片条目，不做瀑布式玻璃卡片。
- 私密状态清晰但不过度警示。
- 新建和编辑页复用统一 Markdown 编辑组件。

### 5.5 公众号 `/wechat` 与 `/wechat/:slug`

- 列表强调来源、发布日期和摘要。
- 详情复用博客阅读系统，允许附加“原文来源”区域。

### 5.6 AI 导航 `/ai`

- 保留搜索和分类为主要任务。
- 工具按紧凑列表或分组书架呈现，避免每个工具都是厚重卡片。
- 颜色只用于类别或状态，不恢复极光渐变。

### 5.7 登录 `/login`

- 使用单张纸面表单和留白构图。
- 水墨植物作为弱化的真实图片资源置于辅助区域。
- 移除发光背景和大型深色玻璃面板。

### 5.8 管理后台 `/admin/*`

- 左侧导航与公开站保持同源视觉，但信息项改为后台任务。
- 仪表盘使用编辑部工作台风格。
- 内容列表使用可扫描表格/行列表。
- 新建、编辑页面将正文编辑区作为核心，发布设置为右侧粘性辅助栏。

## 6. Markdown 阅读系统

### 6.1 服务端渲染

现有 `server/utils/markdown.ts` 只处理标题与段落，无法满足目标。替换为成熟的 Markdown 渲染库，并开启必要能力：

- CommonMark/GFM 基础语法。
- 表格、任务列表、删除线。
- 安全链接属性。
- 代码围栏与语言类名。
- 标题锚点，供文章目录使用。

服务端继续在写入时将 `contentMd` 渲染为 `contentHtml`，不改变数据库字段。

输出 HTML 必须经过安全策略处理，禁止不受控脚本和危险属性进入 `v-html`。

### 6.2 展示样式

建立统一的 Markdown 内容类，覆盖：

- `h1`–`h6`。
- 段落、加粗、斜体、删除线。
- 有序/无序/任务列表。
- 引用块。
- 链接。
- 行内代码与代码块。
- 表格及移动端横向滚动。
- 图片、图注和宽度约束。
- 分隔线。

公开内容详情页全部使用同一个 Markdown 展示组件，避免不同内容类型分别维护样式。

## 7. Markdown 编辑与导入

### 7.1 编辑器选型

采用 Vue 3 兼容的轻量 Markdown 编辑组件，优先评估 `md-editor-v3`：

- 直接绑定 Markdown 字符串。
- 自带编辑、预览和分屏能力。
- 能覆盖常用工具栏、代码块、表格、链接和图片语法。
- 与当前 `contentMd` 数据流直接匹配。

实施前需要核对最新版本、包体积、Nuxt SSR 兼容性、许可证和按需配置。若不满足轻量约束，回退为轻量文本编辑器 + 与服务端一致的 Markdown 预览器组合。

现有 TipTap 组件将被替换，不继续执行 HTML/Markdown 混合判断。历史 `contentMd` 中若存在 HTML，需要保留兼容显示或提供一次性迁移策略。

### 7.2 编辑器布局

- 编辑页默认显示分屏模式：左侧 Markdown 源文，右侧实时预览。
- 小屏默认编辑模式，通过顶栏切换预览。
- 顶部保留编辑、分屏、预览、导入和保存状态。
- 元信息字段保持在正文上方或右侧发布栏，不塞入编辑器内部。
- `Cmd/Ctrl + S` 保存保持有效。

### 7.3 本地导入

导入流程：

1. 用户点击“导入 Markdown”。
2. 打开系统文件选择器，仅接受 `.md`、`.markdown` 和 `text/markdown`。
3. 浏览器使用 `FileReader` 读取 UTF-8 文本。
4. 若当前编辑器已有内容，弹出覆盖确认；空内容直接载入。
5. 文件正文写入 `contentMd`。
6. 当标题为空时，使用文件名去扩展名作为标题建议，不强制覆盖已有标题。
7. 显示导入成功、失败或不支持格式的反馈。
8. 导入后仍需用户点击保存，不自动写入服务器。

首期不解析 YAML Frontmatter，不上传原始文件，不批量导入目录。

## 8. 数据与组件边界

### 8.1 保持不变

- `contents.contentMd` 仍是源内容。
- `contents.contentHtml` 仍是服务端生成结果。
- 现有内容 CRUD API 路径保持不变。
- 标签、可见性、状态、类型和发布时间规则保持不变。

### 8.2 新增或调整的组件边界

- `PaperShell`：公开页面三栏框架。
- `PaperSidebar`：主导航和品牌。
- `ReadingAside`：目录、近期内容与页面辅助信息。
- `ContentList`：博客、笔记、公众号可复用的行列表。
- `MarkdownContent`：统一安全 Markdown 展示。
- `MarkdownEditor`：编辑、分屏、预览、导入和状态提示。
- `ImportMarkdownButton`：文件校验与本地读取。

组件名可按项目现有自动导入约定调整，但职责不得混合。

## 9. 错误处理与可访问性

- 文件格式不支持、读取失败、空文件和编码异常均显示明确中文提示。
- 覆盖已有编辑内容前必须二次确认。
- 编辑器、导航、抽屉和模式切换可使用键盘操作。
- 所有输入框具有可见标签和聚焦状态。
- 图标按钮提供可访问名称。
- 纸张纹理不得导致正文对比度低于可读标准。
- `prefers-reduced-motion` 下关闭非必要动画。

## 10. 验证范围

### 10.1 自动化验证

- 现有单元测试继续通过。
- 新增 Markdown 渲染测试，覆盖表格、列表、引用、代码块、危险 HTML 和标题锚点。
- 新增本地导入逻辑测试，覆盖成功、格式错误、空文件和覆盖确认。
- 新增核心页面结构测试，验证统一布局和 Markdown 组件接入。
- 执行 typecheck、lint、测试和生产构建。

### 10.2 浏览器验证

桌面端至少验证：

- 首页。
- 博客列表和详情。
- 笔记/灵感列表。
- AI 导航。
- 登录页。
- 后台内容列表和编辑页。
- Markdown 导入、编辑、预览和保存主流程。

移动端以 390 × 844 验证相同核心流程，重点检查导航抽屉、编辑模式切换、表格/代码块溢出和主要按钮可达性。

最终以选定的第二版视觉稿作为桌面设计 QA 基准；允许根据真实内容和响应式约束做必要重排，但不得回退到玻璃拟态或极光视觉。

## 11. 非目标

- 不重写后端认证或会话系统。
- 不新增多人协作、评论、版本历史或云端文件同步。
- 不引入完整 CMS。
- 不做批量 Markdown 目录导入。
- 不在首期解析 YAML Frontmatter。
- 不更换数据库或部署方式。
